规则优先级、覆盖关系与冷数据机制

1. 规则构成：每条规则 = 路径范围（前缀匹配 / 精确匹配）+ 动作（归档冷数据 / 移入回收站） + 触发条件（超过 N 个时间单位没有「最近访问 atime / 最近修改 mtime / 创建 ctime」）+ 优先级。

2. 优先级与覆盖：同一文件可能被多条规则命中。 归档与回收站是两个独立的动作，分别裁决；每个动作内部按 优先级数值 ↓ → 路径前缀长度 ↓ → 创建时间 ↑ 排序， 第一条生效，其余标记为「被覆盖」。例如 /data 30 天归档(p120) 会覆盖 / 60 天归档(p50)——预览页直接展示覆盖链，不会悄悄漏过。

3. 触发前撤销（两阶段执行）：文件首次满足条件时不会立刻执行，而是进入 撤销宽限期（--），出现在「即将触发」页并倒计时。 宽限期内可一键撤销：在文件被重新访问/修改、或规则被修改之前，系统不会再次自动触发； 规则停用/删除、文件被访问或移动导致条件不再成立时，待触发动作会自动撤销并留痕。

4. 归档与透明取回：归档时文件独占的块从 DataNode 热副本下沉到 NameNode 的 冷归档库（写入后复核 sha256，内容不丢），块表标记 tier=cold 且不再参与热副本恢复队列； 被多个文件共享的去重块若仍有热引用，则保留热副本。任何下载 / 预览 / 缩略图 / 历史版本读取都会自动取回：冷库校验 → 重新按副本数流水线复制回 DataNode → 块层回到 hot → 删除冷库副本。调用方完全无感知，响应头 X-Restored-Blocks / X-From-Cold 会标注本次取回的块数。

5. 自动回收站：到期文件走与手动删除完全相同的删除保护路径进入回收站， 回收站条目记录来源规则；可在回收站页恢复（恢复后仍是归档层，访问时同样自动取回）。

6. 有据可查：每次归档 / 取回 / 移入回收站 / 撤销都写入执行历史与系统审计日志， 可按文件路径反查「它被哪条规则动过」；文件详情抽屉中也有同样的生命周期视图。
